# Trust-Gap Mitigations · Juno

_Module 4. Generated by `M4 - AI-UX Trust Gap Checker.html`. Feature: Juno PM v1 (M1 prototype, no RAG yet). Paste over `04-ai-ux/trust-gaps.md`._

## Trust gaps

| Gap | Where it shows up | User cost | Mitigation |
|---|---|---|---|
| **The Black-box Gap** | Can the user see why the AI decided? | User will lose trust after one failure (1/5 closed) | Show work / reasoning: Every Juno incident gets a “Why?” section that shows the main reason for the recommendation and links to the Slack messages, Jira issues, and strategy information it used. |
| **The Hallucination Gap** | Could this confidently be wrong? | Noticeable but recoverable (3/5 closed) | Juno shows how sure it is and lets the PM check the proof. Every Juno incident shows confidence level and links to the sources it used. If Juno is missing information or is not sure, it clearly says “Low confidence”. Never communicates absolute certainty.  |
| **The Control Gap** | Can the user steer or stop? | User will lose trust after one failure (1/5 closed) | PM cannot intervene.  Add clear Accept, Edit, Dismiss, and Override buttons to every Juno incident. The PM should also be able to stop Juno from taking any next step. |
| **The Intelligence Tax** | Is the latency / privacy / cognitive load worth the value? | User will lose trust after one failure (1/5 closed) | PM cannot currently intervene. Connect Juno directly to Slack and Jira, and add simple controls so the user can accept, change, or stop what Juno is doing without leaving their normal workflow. |

## Highest-priority fix

**The Black-box Gap** (1/5). Show work / reasoning: Every Juno incident gets a “Why?” section that shows the main reason for the recommendation and links to the Slack messages, Jira issues, and strategy information it used.

## Verdict

**Unsafe.** Do not ship. At least one trust gap is wide open. Re-spec from the AI-UX Readiness Checklist Level 1.
