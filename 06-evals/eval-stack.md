## What "good" means

At least 80% positive feedback, fewer than 15% major edits or overrides, and fewer than 20% abandoned recommendations.

- Active: smiley face or frown on each Juno recommendation; edit  before using the recommendation; short written feedback when the PM gives a frown.
- Active: Weekly survey asks PM for feedback, do they find it useful (Y/N)?
- Passive: whether the PM accepts or dismisses the recommendation and how much they change it.

## Golden set

Use 200 past P0 cases where the PM already decided what the right top risks were.
Keep the set updated when we learn something new or after a major incident.

## Release gate

**Hard gates (auto-block):**

- Any PII leak blocks the release.
- Any serious safety or refusal failure blocks the release.
- Any breaks, dead-ends, or failures block the release. 
- Any citation that is missing, made up, or points to the wrong source blocks the release.

**Soft gates (PM sign-off):**

- If response time is consistently too slow, the PM has to decide if the value is still worth the wait.
- If Juno’s accuracy drops below the target but there are no safety issues, the PM can review the trade-off and decide whether to hold or ship.
- If users are making too many edits or overrides, the PM reviews the pattern before release.
